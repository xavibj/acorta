# 005 — CLI

Un solo ejecutable, `acorta`, con subcomandos. La CLI trabaja directamente sobre la base de datos a través de `shortener` (no llama a la API): funciona con el servidor parado.

`main` solo llama a `run(args []string, stdout, stderr io.Writer) int` y sale con el código que devuelve. Los tests se escriben contra `run`.

## Subcomandos

```
acorta serve [-addr :8080] [-db RUTA] [-base-url URL] [-token TOKEN]
acorta add   [-alias ALIAS] [-ttl DURACIÓN] [-db RUTA] [-base-url URL] URL
acorta list  [-db RUTA]
acorta rm    [-db RUTA] CÓDIGO
acorta version
acorta help
```

Los flags van antes del argumento posicional (así funciona el paquete `flag`).

## Configuración

| Qué | Flag | Variable de entorno | Por defecto |
|---|---|---|---|
| Fichero de la base de datos | `-db` | `ACORTA_DB` | `acorta.db` |
| URL base de las URL cortas (`serve` y `add`) | `-base-url` | `ACORTA_BASE_URL` | `http://localhost:8080` |
| Dirección de escucha (solo `serve`) | `-addr` | — | `:8080` |
| Token de API (solo `serve`, spec 008) | `-token` | `ACORTA_TOKEN` | — (obligatorio) |

El flag gana a la variable de entorno, y esta al valor por defecto. Una variable de entorno vacía cuenta como no definida. A la URL base se le quita la barra final.

## Códigos de salida

| Código | Significado |
|---|---|
| 0 | Todo bien |
| 1 | El comando se entendió pero falló: validación, enlace no encontrado, base de datos |
| 2 | Uso incorrecto: subcomando o flag desconocido, falta o sobra un argumento |

Los errores se escriben en `stderr`, uno por línea, con el prefijo `error: `. En `stdout` solo va el resultado.

El **mensaje de uso** de un subcomando es una línea en `stderr` con `uso: ` seguido de su sinopsis, tal como está en «Subcomandos» (`uso: acorta rm [-db RUTA] CÓDIGO`). Un flag desconocido o mal usado es un uso incorrecto: una línea `error: ` con el detalle que da el paquete `flag` (en inglés: es de la biblioteca estándar y no se traduce), el mensaje de uso y salida 2.

## Criterios

- **CLI-01** — `acorta add https://example.com` crea el enlace, escribe en `stdout` solo la URL corta seguida de salto de línea (`http://localhost:8080/k3x9ab`) y sale con 0.
- **CLI-02** — `acorta add -alias promo https://example.com` escribe `http://localhost:8080/promo`.
- **CLI-03** — `acorta add -ttl 72h https://example.com` crea el enlace con caducidad dentro de 72 horas. `-ttl` es una duración de Go (`90m`, `72h`); sin `-ttl` el enlace no caduca. Si el valor está vacío, no lleva unidad (`72`), no se puede interpretar o no es mayor que cero: `error: ttl: debe ser una duración positiva (ejemplos: 90m, 72h)` y salida 2.
- **CLI-04** — Si la validación falla, escribe en `stderr` una línea `error: …` por cada mensaje de la spec 002, no escribe nada en `stdout` y sale con 1. Lo mismo con un alias en uso.
- **CLI-05** — `acorta add` sin URL o con más de un argumento: mensaje de uso en `stderr` y salida 2.
- **CLI-06** — `acorta list` escribe una tabla con las columnas `CÓDIGO`, `VISITAS`, `CADUCA` y `URL`, una fila por enlace en el orden de LIS-01, con las columnas alineadas con espacios (`text/tabwriter`); cuántos espacios exactamente no forma parte del contrato. `CADUCA` muestra la fecha en RFC 3339, `nunca` si no tiene, o `caducado` si ya ha caducado.
- **CLI-07** — `acorta list` sin enlaces escribe `No hay enlaces.` y sale con 0.
- **CLI-08** — `acorta rm promo` borra el enlace, escribe `Borrado: promo` y sale con 0. Si no existe: `error: enlace no encontrado` y salida 1. Sin código o con más de uno: mensaje de uso y salida 2.
- **CLI-09** — `acorta serve` abre la base de datos, escribe `acorta escuchando en http://localhost:8080` (según `-addr`: con `:9090` dice `http://localhost:9090`; con `127.0.0.1:9000`, `http://127.0.0.1:9000`) y sirve `server.Handler` con los estáticos embebidos (`server.Static()`). La función que escucha se inyecta, para probar el arranque y sus errores sin abrir sockets. Si no puede escuchar: `error: …` y salida 1.
- **CLI-10** — `-db`, `-base-url` y `-token` siguen la precedencia flag > entorno > por defecto.
- **CLI-11** — `acorta version` escribe `acorta ` seguido de la versión (`dev` si no se fijó al compilar).
- **CLI-12** — `acorta`, `acorta help` y `acorta -h` escriben la ayuda con la lista de subcomandos y salen con 0. `-h` dentro de un subcomando (`acorta add -h`) escribe en `stdout` su mensaje de uso y la lista de sus flags, y sale con 0. Un subcomando desconocido escribe `error: subcomando desconocido "x"` más la ayuda en `stderr` y sale con 2.
- **CLI-13** — Si no se puede abrir la base de datos (ruta en un directorio que no existe): `error: …` y salida 1. Vale para `add`, `list`, `rm` y `serve`; `serve` no llega a escuchar.
