# 006 — Interfaz web

Una sola pantalla, en español, para crear enlaces y ver los que hay. Vue 3 con Vite y Tailwind (spec 001). Habla con la API de la spec 004 y no contiene reglas de negocio: los errores que muestra son los que devuelve la API.

## Estructura

```
web/
  index.html
  vite.config.js        build.outDir = ../server/static/dist, proxy de /api al servidor Go
  src/
    main.js
    api.js              fetch → { ok, data, errors }
    App.vue             estado: lista de enlaces, carga, errores
    components/
      LinkForm.vue      formulario de creación
      LinkList.vue      listado
      CopyButton.vue    botón Copiar / Copiado (lo usan el formulario y cada fila)
    *.test.js           Vitest + @vue/test-utils
```

## Diseño

- **Mobile first**: una columna, sin anchos fijos; a partir de `md` el contenido se centra con un ancho máximo. Sin scroll horizontal a 360 px.
- Botones y campos de al menos 44 px de alto. Cada campo con su `<label>`.
- Tema claro y oscuro según el sistema (`prefers-color-scheme`).
- Los mensajes de estado y de error están en una región `aria-live="polite"`.
- Las URL largas se cortan visualmente (con puntos suspensivos o salto de línea), nunca desbordan.

## Formulario

Campos: **URL** (`type="text"`, `inputmode="url"`), **Alias** (opcional) y **Caducidad** (desplegable: Nunca, 1 hora, 1 día, 7 días, 30 días). Botón **Acortar**.

- **WEB-01** — Al enviar, hace `POST /api/links` con `url`, con `alias` solo si se ha escrito y con `expires_at` solo si la caducidad no es «Nunca» (el momento actual más el plazo elegido, en RFC 3339 UTC).
- **WEB-02** — Mientras la petición está en curso, el botón y los campos están deshabilitados.
- **WEB-03** — Si se crea (`201`): muestra la URL corta nueva destacada, con su propio botón **Copiar** (además del que tiene su fila en el listado); vacía el formulario (URL y alias en blanco, caducidad otra vez en «Nunca»); y el enlace aparece el primero del listado sin recargar la página ni volver a pedir la lista.
- **WEB-04** — Si la API responde con errores (`400`, `409`, `503`): los muestra **todos**, tal como llegan, debajo del formulario, y conserva lo que el usuario había escrito.
- **WEB-05** — Si la petición no llega al servidor o la respuesta no es JSON: muestra un único mensaje, `No se ha podido conectar con el servidor.`
- **WEB-06** — Al editar cualquier campo desaparecen los errores y el resultado del envío anterior.
- **WEB-07** — El botón Acortar está deshabilitado mientras la URL esté vacía.

## Listado

- **WEB-08** — Al cargar la página hace `GET /api/links` y muestra los enlaces en el orden que llegan.
- **WEB-09** — Cada enlace muestra: la URL corta (enlace que abre en otra pestaña), la URL de destino, las visitas (`0 visitas`, `1 visita`, `2 visitas`) y la caducidad: nada si no tiene; `Caduca el 31/12/2026 23:59` si tiene, en la hora local del navegador y con el formato `dd/mm/aaaa hh:mm`; o solo la etiqueta `Caducado`, sin la fecha, si `expired` es `true`.
- **WEB-10** — Sin enlaces muestra `Aún no hay enlaces. Crea el primero arriba.`
- **WEB-11** — **Copiar** copia la URL corta al portapapeles y el botón muestra `Copiado` durante dos segundos.
- **WEB-12** — **Borrar** pide confirmación (`¿Borrar /promo?`). Si se confirma hace `DELETE /api/links/{código}` y, con `204`, quita el enlace del listado. Si falla, muestra el error y el enlace sigue en el listado. La respuesta `204` no tiene cuerpo: no es un error de conexión.
- **WEB-13** — El botón **Actualizar** vuelve a pedir el listado (las visitas cambian en el servidor; no hay sondeo automático).
- **WEB-14** — Si falla la carga del listado, sea por la red o por una respuesta de error, muestra `No se ha podido cargar la lista de enlaces.` con un botón **Reintentar** que vuelve a pedirla.

## Verificación

- Los criterios WEB-01 a WEB-14 se comprueban con tests de componentes (Vitest), con `fetch` y el portapapeles simulados.
- `npm run build` debe terminar sin errores: es lo que caza los fallos de sintaxis y de plantillas antes de que lleguen al navegador.
- Antes de dar la fase por buena, el orquestador recorre la pantalla en un navegador real contra el binario compilado, a 390 px y a 1280 px: crear, error de validación, copiar, visitar, actualizar, borrar. Los tests de Go no ejecutan JavaScript.
